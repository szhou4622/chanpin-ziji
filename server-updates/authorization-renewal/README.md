# 设备会话续期可靠性

本修复修改产品经营报告客户端，不替换共享授权服务、不修改数据库结构。现有服务器的 `/api/license/activate` 已支持保留设备凭证重新签发会话。

## 请求契约

普通续期携带现有 `Authorization: Bearer <device_session>` 和 `X-Device-Credential`，请求体同时包含 `current_code_id` 与原 `device_credential`。**不发送 `credential_refresh=true`**：该标志会让现有服务器立即更换长期凭证及其版本，不适合可重试的普通续期。

- 响应必须保持同一主授权、设备绑定、换机次数和设备凭证；不得充值或自动换绑。
- 只有临时会话更新。回复丢失或本地新会话尚未保存时，旧凭证和仍有效的旧会话可以继续验证并重试。
- 会话真正过期或缺失时，保留用户“一键恢复本机授权”的确认步骤，发送已保存设备凭证，不发送过期会话。
- 仅完全没有设备凭证的旧协议升级继续使用 `credential_refresh=true`。
- 管理员解绑、停用、真实到期和凭证撤销仍然立即生效，不通过自动激活撤销这些操作。
- 已被旧版本轮换且本机从未保存的新凭证无法从服务器哈希中恢复；此类既有失配仍需要管理员处理一次。新版本不再在普通续期中制造该失配。

## 验证

`product-operation-report-app/scripts/regression-main.ts` 使用独立测试目录，覆盖续期应答丢失、保存前崩溃/重启、旧备份恢复、异常凭证响应、缺失会话、明确过期后的确认恢复、续期中被管理员撤销或解绑。测试必须同时保留设备码和余额，且不得静默重绑。

真实接口验收脚本只在授权服务器上运行：

```sh
python3 -B smoke_stable_renewal.py --run-live
```

它新建一个随机机器码和限额 100 积分的独立测试授权，不调用模型，不使用客户激活码。验证丢弃回复后的重试、两个客户端同时续期、显式恢复请求与错误凭证拒绝；比较数据库中的凭证哈希、版本、绑定、换机次数和接口余额是否保持一致。凭证仅驻留内存，输出只含脱敏验证结果。`finally` 中停用精确匹配本次标记的测试码，并冻结存在的测试钱包。

升级客户端即可使用新契约。不得为发布本修复重启共享授权服务或批量解除用户绑定。GitHub CI 运行客户端回归；线上验收结果记录在同目录的 `verification-20261013.json`。
