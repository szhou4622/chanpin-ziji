# 正式 V2 代理的豆包迁移

本目录保留 2026-10-12 正式服务器已有的 V2 精确积分实现，在该实现上接入
`doubao-seed-2-1-pro-260915`。不要用 legacy 的 `points-proxy-v1` 覆盖正式服务。

原正式代理 SHA256：`460ce2d6c5c3984a0e339a2451fc0536bc2b0289b53e9683e4d8a2d4aa5039c4`。
`provider_keyring.py` 保留服务器原实现；`por_billing_v2.py` 在原账本结构上补齐了下面的并发与恢复边界。

- 所有新模型任务实际调用方舟豆包 2.1 Pro。已有安装包发送的五个旧模型名称仅作为兼容别名，服务器在验证时转为豆包，不再请求旧供应商。
- 普通任务使用 Chat API。清洗、摘要、产品信息及合法的词云提取/归一任务关闭思考；经营分析固定使用 `reasoning_effort=low`，不再落到模型默认 high。服务端按任务及严格匹配的词云任务键选择策略，不接受客户端覆盖。输出及思维链共同受 `max_completion_tokens` 限制。
- 全局输出上限默认 16,000 Token；清洗固定 12,000、产品信息 8,000、旧分析步骤 12,000、摘要 3,500，其余分析任务最多 16,000。预留积分按同一实际请求上限计算，最终只按实际用量结算。语义清洗不复写整张表，原批次边界、任务 ID 和已保存成功结果保持兼容。截断结果仍拒收、零成功扣费。
- 对标搜索任务使用 Responses API，固定 `reasoning.effort=low` 和基础联网搜索。搜索来源继续通过代理可信事件返回。
- 支持结果确认的客户端仍在结果完整且本地保存确认之后扣费；失败或不完整输出不生成成功证明。旧客户端继续使用既有 legacy 结算模式。
- 使用带 SHA256 校验的 `ark-standard-20261012.json`，以人民币按实际 Token 计费：非缓存输入 6 元、输出 30 元、缓存命中 1.2 元/百万 Token。继续使用服务器原积分倍率、四舍五入、中央账本和幂等行为。
- 旧模型价格只用于历史待结算记录，按原固定 7.2 汇率转换后保留；不会重新收费或追收历史任务。V2 仍按原合同仅向用户收取模型 Token 费用，搜索资源费由平台承担。
- Key 仅保存在服务器 `/etc/product-operation-report/provider-keys.json`。不要写入仓库、客户端或安装包。

部署前运行 `python -B -m unittest discover -p 'test_*.py'`，验证真实回环 HTTP、全部任务、旧模型别名、结果确认、重复确认、中断零扣费及对抗性边界。
部署必须备份正式代码、Key 配置和计费环境；升级代码与价目表后重启正式服务，验证公网健康、真实模型调用和精确积分确认。

不要仅从代码默认值判断输出上限：部署后核对运行进程的 `POR_MAX_OUTPUT_TOKENS`。用 `deploy_output_budget.py --from-tokens 12000 --to-tokens 16000 --check-only` 验证明确的旧值与目标值，再去掉 `--check-only` 执行。脚本只改这一条配置，暂停新请求并等待旧请求退出，保留私有配置备份，重启后核对实际值并恢复 Nginx；不改密钥、价目表或余额。

## 完整客户端验收

短句、单个清洗请求不能替代全报告验收。`report_test_authorization.py create <私有目录>/authorization.json` 创建上限 2,000 积分的专用测试授权，验证码仅写入私有文件。通过 SSH 安全传到本机工作区的 `.codex-runtime/` 后，在应用目录运行：

```text
node scripts/run-full-report-e2e.cjs --source-profile <已有清洗完成的测试目录> --authorization <私有授权文件> --output <全新验收报告目录>
```

脚本只复制当前项目及校验通过的内容 blob，不复制真实授权；使用真实 renderer/store、preload IPC、主进程、代理及账本，从 8 份已清洗结果续跑六模块与词云，并验证保存重开、证据引用及 Markdown/HTML/Word 导出。若中途需要修正，可对同一私有工作目录显式加 `--resume`，保留已完成任务与扣费证明。结束后必须在服务器运行 `report_test_authorization.py freeze <原私有授权文件>`，确认无运行请求，再清理私有授权、测试配置目录和样本，仅保留报告与去敏验收记录。

## 审查修复

- 完整结果在等待回执、等待账单、结算重试期间继续占用余额。合法实际用量高于预估时按实际费用保护余额；过期回执恢复也重新执行余额准入。没有提前扣费或重算历史已结算金额。
- 并发合法确认复用相同账单和中央交易；冲突证明拒绝。旧失败身份、迟到回执不能覆盖新尝试。
- Responses 文本片段保留原始空白；明确失败事件不能被后续完成事件覆盖。终局用量缺失、矛盾、为 null 或出现在完成前时，不生成可扣费凭证。终局全文与已发片段不一致时也拒绝完成。
- 搜索只把成功完成的调用和有效引用作为可信证据；明确零次搜索不会标记已验证。新增 `por_v2_report_attempts` 记录本次升级后的 V2 报告准入，和原 legacy 已提交/正在运行的搜索共同执行每报告上限。原 V2 没有保存报告 ID，既有记录不猜测补录。
- 客户端钱包显式启用 V2；完整结果的保存/确认失败保留原证明用于恢复。业务资料变更时，旧证明与当前业务输出分开处理。停止操作覆盖并发调用与重试等待。

现有 V2 服务器使用 `deploy_review_fixes.py --check-only` 预检，确认基线匹配后运行 `deploy_review_fixes.py`。
该脚本仅替换代理和计费状态机两份代码；短时暂停新业务请求并等待旧请求退出，保留健康检查。它备份原代码、Nginx 和数据库快照，失败恢复代码和 Nginx，**不会回滚数据库、用户余额、Key 或价目表**。临时部署包应在验证后清理，审计备份保留。
