# v1.1.1

- 报告引擎升级为6个经营模块：产品信息、成交人群、内容素材、卖点提炼与排序、用户VOC、人群卖点场景，报告结构更直观。
- 成交人群按用户实际上传的平台分别生成画像看板；上传几个平台就展示几个平台，不混合不同平台的百分比口径。
- 多平台核心人群TOP5、主力来源和决策结论固定展开；各平台长篇原始画像明细按需查看，打印时自动完整展开。
- 内容素材判断按自有素材、竞品素材和补充机会分别可视化，保留具体框架、数据依据和可复用方向。
- 用户VOC固定生成隐形需求、购买顾虑、高频问题、正向反馈四组TOP10；缺组、缺项或占位词会自动纠正，不再把TOP编号当作需求词。
- 用户选择的资料归属、平台和信息类型会贯穿清洗、分析与报告；结构化表格优先在本机完整读取，减少等待和重复积分消耗。
- 模型线路零输出或瞬时异常时可安全切换备用线路；已完成模块和清洗结果继续保留，不重复执行成功任务。
- 旧版项目继续兼容，历史报告、HTML/Word导出、激活、积分、换机和自动更新流程保持不变。
- 修复 Windows 干净安装环境因换行符差异无法读取内置模块提示词的问题，三平台使用同一套经过哈希校验的分析规则。

# v1.0.1

- M4七维对标固定使用服务器端 `gpt-5.6-sol`，其他模块和最终报告继续使用 `gpt-5.5`。
- 只有CCG返回结构化搜索调用和公网来源链接时才显示“已核验公开来源”，不再把普通模型正文误记成联网搜索。
- 天猫、抖音、视频号和小红书按来源分别标记找到或未找到；无可靠来源时基于上传资料继续分析，其余明确写“暂无可靠公开资料”。
- M4改为最多2个维度并发，单维度自动补试1次；成功维度和来源证据可安全恢复，避免重复调用和重复扣费。
- 拦截私网、本机和危险协议来源，并禁止“品牌A、某品牌、TOP1”等占位名称进入对标报告。

# v0.4.2

- 软件升级后先验证本机设备会话和安全凭据，正常授权直接进入，不再仅凭保存的激活码自动重新绑定。
- 管理员解绑、激活码禁用、授权过期、机器不匹配和设备凭证撤销使用独立状态；后台解绑后旧电脑不会在重启时自动回绑。
- 设备会话剩余不足7天时，在服务器验证成功后自动安全轮换；会话已经过期时可由用户确认后一键恢复，无需再次输入原激活码。
- 已保存设备码成为最高优先级，系统硬件标识偶发读取失败时也不会生成新的设备码。
- Windows凭据或macOS钥匙串暂时不可用、加密文件损坏和文件不存在会分别提示，软件不会覆盖仍可能恢复的原授权文件。

# v0.4.1

- 软件升级后自动读取系统安全存储中的原激活码并完成服务器验证，不再要求普通用户重新填写或手动点击。
- 本机设备会话或设备凭证失效时，使用原激活码、原授权编号和稳定机器码安全领取新凭证，不增加积分、不改变设备绑定。
- 授权恢复失败时保留历史项目和报告，只有服务器明确禁用、解绑或机器不匹配时才阻止新的云端分析。
- 联系作者二维码浮层提升到内容区上方并放大显示，避免二维码被页面遮挡或难以扫描。
- macOS M 系列和 Intel 安装包启用 Developer ID 正式签名、Apple 公证、票据附加和 Gatekeeper 验证。
- 发布 Windows x64、macOS Apple Silicon 和 macOS Intel 三个平台安装包，并同步正式自动更新服务器。

# v0.4.0

- 大项目先生成一次通用证据台账，8个分析步骤直接复用，避免每一步重复读取全部资料。
- 模型请求启用稳定前缀缓存，供应商不支持时自动回退，不影响报告生成。
- 文件解析提升为两个隔离进程并行，批量上传等待时间更短，单个损坏文件仍会被隔离。
- 删除客户端本地积分价格表和扣费账本，余额、流水与价格统一以服务器返回为准。
- 拆分状态错误处理、项目持久化和联系方式/积分样式模块，降低超大文件修改风险。
- 新增ESLint、Vitest、EditorConfig和CI门禁，核心纯函数可快速单测。
- 清洗和分析页面增加预计耗时，离线宽限与授权失效使用不同提示。
- 大表格清洗改用更小批次，首个模型数据块最多等待180秒；开始返回后仍保留90秒无数据保护，减少正常慢请求被误判失败。
- 清洗会按资料数量自动分配批次并发，单文件最多3批并行，50份资料时总并发仍限制为4，兼顾速度、内存和积分安全。
- 正式代理模式会清理旧版遗留的本地模型配置和备份，开发测试也默认走服务器积分代理，避免模型请求绕过积分结算。
- 并发批次遇到其他任务暂时锁定积分时会等待结算后自动继续，只有真实余额仍不足时才提示充值。
- 结构可靠的Excel/CSV改为本机完整读取、去除空列和重复AI中间列、逐行添加证据ID，不再调用清洗模型或扣清洗积分；未知结构仍安全回退。
- 本次表格整理规则升级会使旧清洗缓存失效；结构化表格重新整理在本机完成，不会重复产生清洗积分。
- 顶部联系入口改为“联系作者”，首次交互时通过主进程读取后台图片；支持HTTPS校验、禁用状态、本地缓存和内置图片兜底。

# v0.3.9

- 清洗完整性改为按CSV首列逐行核对证据ID，集中抄写ID或缺少数据行不再被判定为清洗完成。
- 本次升级会重新清洗一次已缓存资料，因为旧版清洗结果的完整性无法可靠保证；这是正常升级行为，不是重复故障。
- 授权服务器短时不可连接时保留最近一次成功验证，72小时宽限期内不中断正在生成的报告。
- 授权刷新增加主进程互斥和60秒节流，模型任务完成后只读取轻量积分钱包，不再反复写授权文件。
- 积分窗口显示服务器真实余额和最近流水，报告完成后显示本次消耗和剩余积分。
- 表格无法逐行识别时明确提示降级原因；项目资料块缺失时其余项目内容仍可恢复并提示重新上传。
- Token日志自动轮转，来源告警可跨重启保留；清洗保存、表格解析、分析分组和报告缓存完成性能优化。
- GitHub Actions 正式运行核心回归、更新流程与HTML视觉测试后才允许打包发布。

# v0.3.3

- 更换电脑改为当前设备安全解绑，新电脑直接输入原激活码重新绑定，不再使用换机码。
- 设备解绑改用 `/api/license/device/unbind`，启动校验改用 `/api/license/device/status`。
- 设备会话和设备凭证在本机加密保存；解绑成功后立即清除旧设备授权和本地积分显示。
- 服务器保留真实剩余积分，新电脑绑定时按服务器余额恢复，不重新发放激活码初始积分。
- 旧版本地授权无需重新输入激活码，可直接清除本机授权；已有服务器授权则使用设备凭证直接解绑。
- 兼容 v0.3.2 服务器授权：缺少设备凭证时由软件在原电脑自动刷新，再执行解绑。
- 新激活统一以服务器为准，客户端不再离线接受内置激活码；旧哈希表只用于识别已经激活的本机旧记录。
- 服务状态显示当前主激活码，默认隐藏并支持显示、复制；主激活码仅加密保存在当前电脑。
- 积分码只给当前钱包增加积分，不覆盖主激活码或设备绑定；重复输入同一积分码不会重复入账。
- 解绑失败、冷却期、次数限制或机器码不匹配时保留本机授权，并显示服务器返回的原因。

# v0.3.2
